# Module note template

<!--
Use this file as the shape for every module note in curriculum/.
The validator checks the six `##` sections, their order, and that each one has content.
-->

# <Id> - <Title>

## What

<!--
One or two paragraphs: the subject of the module, in the learner's terms.
Say what the learner will be able to do afterwards that they cannot do now.
No marketing, no "in this exciting module".
-->

## Why it comes here

<!--
The position of this module in the series. Name the specific thing that breaks if the
learner skips it, or arrives here without the previous module.
-->

## What gets built

<!--
The components, in the order they are built. Bullets, one line each.
-->

## Acceptance criteria

<!--
Checkable statements. Each one must be true or false without asking a human to guess.
"The code is good" is not a criterion. "The retry path does not write twice" is.
-->

## The artifact

<!--
What the learner ships, described the way the learner would describe it.
Include what evidence to keep with it: the test output, the schema diff, the numbers.
-->

## Notes

<!--
Traps, warnings, and the conventions of this series: no paid APIs, mock numbers are
labelled SIMULATED, secrets come from environment variables only.
-->
